# Product Discovery Process

Use this before committing major product work.

## 1. Identify the Problem
Start from a real farmer problem in `../02-farmer-problems/`.

## 2. Understand the User
Identify user role, farm type, current workflow, current workaround and buying influence.

## 3. Measure the Problem
Estimate frequency, economic impact, time impact, operational risk and number of affected users or farms.

## 4. Collect Evidence
Use interviews, observation, operating experience, user feedback, data and market research.

## 5. Define the Desired Outcome
Describe what should improve for the farmer.

## 6. Explore Solutions
Compare multiple possible solutions before selecting one.

## 7. Test the Riskiest Assumptions
Validate value, usability, feasibility and data availability before large engineering investment.

## 8. Define MVP
Select the smallest reliable workflow that can create and measure real value.

## 9. Prioritize
Use the prioritization framework and compare against other opportunities.

## 10. Write Requirements
Only after the problem, user, outcome and MVP are sufficiently understood.

## Discovery Output
A major feature should normally link to:
- farmer problem;
- persona / JTBD;
- research evidence;
- desired outcome;
- business case;
- MVP scope;
- success metrics;
- assumptions and risks;
- requirements.
